# Взгляд глазами пользователя (2026-08-23)

Состояние на 2026-08-23. Ревью не по коду, а по пути пользователя: карточка
на pub.dev → README → первый `dart run` → справочник API. Всё, что помечено
«проверено», проверено запуском, а не рассуждением.

## Как проверялось

Отдельный пакет вне репозитория (`scratchpad/newuser`), зависимость
`team_logger` по `path:`, чистый `dart pub get`. API-справочник — `dart doc`
в отдельный каталог, поиск по `index.json` и по странице библиотеки. Архив —
`dart pub publish --dry-run`.

## Что хорошо

- README (2104 строки, 11 разделов, оглавление, 43 воспроизводимых кадра) —
  сильно выше среднего по pub.dev.
- CHANGELOG написан прозой, с причиной изменения и пометками
  `[breaking changes]`.
- Честность там, где обычно молчат: size settings названы rotation/retention
  targets, а не hard caps (README:1760); `output` синхронный и почему;
  «один вызов на строку, не на лог»; iOS-баг со ссылкой на upstream.
- Раздел про ленивость точно объясняет, что публикаторные фильтры
  срабатывают уже после вычисления замыкания.
- Полы зависимостей в `pubspec.yaml` прокомментированы причиной (пины
  Flutter 3.27), а не просто проставлены.
- `dart pub publish --dry-run`: 0 предупреждений, 183 КБ.

## Что плохо (проверено)

1. **Нет пути «просто запустить».** `Logger('app').i('hi')` не печатает
   ничего и ни на что не жалуется: уровень по умолчанию `Levels.off`
   (`logger_builder`, `custom_logger.dart:35`) **и** publisher не задан —
   два молчаливых затвора сразу. `ConsoleLogPrinter` требует `rows:`,
   `LogRow` требует `maxLength`. Минимальная рабочая конфигурация —
   `ConsoleLogPrinter(rows: const [LogRow.singleLine(children: [LogMessage()])])`
   — в README не встречается: Quick Start сразу даёт ~25 строк layout'а.

   **Вердикт (2026-08-23): закрыто.** `6ad58da`: в начало
   `## Quick Start` добавлены оба затвора и пятистрочный минимум. Осталась
   отдельная мысль про `ConsoleLogPrinter.simple()` — она открыта, решения
   владельца нет.

   **Вердикт (2026-08-24): закрыто полностью.** Владелец решил делать не
   `simple()`, а умолчание для `rows`: `ConsoleLogPrinter()` теперь
   собирается сам, `rows` по умолчанию `ConsoleLogPrinter.defaultRows`
   (120 столбцов, раскладка Quick Start). Спека —
   `2026-08-24[1]-default-rows-spec.md`. Второй затвор из находки, `level`,
   остаётся: логгер по-прежнему надо включить.

2. **Реэкспорт `logger_builder` не попадает в API-справочник.** `dart doc`:
   `MultiPublisher`, `TransformPublisher`, `AsyncPublisher`,
   `CustomLogPublisher`, `Lazy`, `Levels` отсутствуют и в `index.json`, и на
   странице библиотеки (проверено: `grep -c MultiPublisher index.json` → 0).
   При этом `MultiPublisher` и `TransformPublisher` используются в примерах
   README (§8, §10), а само имя `logger_builder` в README не встречается ни
   разу. Пользователь читает рабочий пример и не находит класс в справочнике.

   **Вердикт (2026-08-23): снято — находка неверна.** Проверялась
   на локальном `dart doc`; на pub.dev классы документированы полноценно, у
   `MultiPublisher` своя страница `team_logger/MultiPublisher-class.html` со
   списком в классах библиотеки `team_logger`. Локальный `dart doc` не
   разрешает элементы зависимости так, как dartdoc на pub.dev. Уцелела лишь
   часть про необъяснённое родство пакетов — она закрыта отдельно, см.
   «непонятно» ниже.

3. **`CustomLogPublisher` назван «the seam for anything else»
   (README:427) — и всё.** Ни раздела «свой publisher», ни примера отправки
   в бэкенд/Sentry. Для библиотеки «для больших команд» это вопрос номер
   два после «как включить».

   **Вердикт (2026-08-23): закрыто.** `f696834`: новый §12
   «Writing Your Own Publisher» — фабрика из функции, класс с состоянием,
   что несёт `Log`, синхронность `publish` и поведение исключения внутри
   `MultiPublisher`.

4. **Ничего про релизные сборки.** В README нет ни `kDebugMode`, ни «как
   выключить в проде», ни цены выключенного лога — при том что
   `logger_builder` продаёт себя строкой «good performance when disabled».

   **Вердикт (2026-08-23): закрыто.** `f696834`: в §3 добавлен
   `#### Logs in a Release Build` — `kDebugMode`,
   `bool.fromEnvironment('dart.vm.product')`, и что на компиляции ничего не
   вырезается.

5. **Строки добиваются пробелами до `maxLength`.** Проверено: `maxLength: 60`
   + `noColors` → `short` и 55 пробелов до конца строки. В консоли это
   нужно (фон, правый `tail`), при перенаправлении в файл или агрегатор —
   хвостовой мусор. Выход — `LogRow.singleLine`, но об этом нигде не сказано.

   **Вердикт (2026-08-23): закрыто.** `6ad58da`: абзац в §1 после
   `LogConstraints`.

6. **Ширина терминала не определяется автоматически.** `maxLength` всегда
   руками; `stdout.terminalColumns` не используется. `team_logger_io.dart`
   уже существует — место для такого хелпера есть.

   **Вердикт (2026-08-23): открыто.** Решения владельца нет.
   Работа не документационная: `LogRow` — `const`, `maxLength` — `int`,
   автоширина требует рантайма, то есть новой формы. Начинать со спеки.

   **Вердикт (2026-08-24): отклонено, объяснено в README.** Владелец
   заметил, что современные терминалы оконные и ширина в них меняется, —
   и это довод не за слежение, а против всей затеи. Лог **дописывается, а
   не перерисовывается**: строка, ушедшая на 120 столбцов, останется такой
   в скроллбэке, сужение окна не переверстает уже напечатанное, и принтер,
   следящий за окном, положил бы в один лог две сетки. Сетка, меняющаяся на
   середине, хуже слишком широкой — а сетка и есть то, ради чего `LogRow`
   существует. TUI такое решить может, потому что владеет экраном; логгер
   дописывает, у него другой контракт.

   Три довода помельче, каждый самостоятельный: ширина stdout не описывает,
   куда уходит вывод (`output` может быть файлом, `dart:developer`,
   агрегатором; во Flutter stdout обычно не терминал); в пайпе
   `stdout.terminalColumns` **бросает** `StdoutException` (проверено), то
   есть хелпер всё равно требует `hasTerminal` и запасной ширины — числа,
   которое выбирает пользователь; SIGWINCH нет на Windows.

   Кто действительно хочет — уже может: переприсваивание `log.publisher` на
   ходу работает, сквозная нумерация переживает подмену (проверено).
   В README §1 добавлен абзац с обоими рецептами и с объяснением, почему
   пакет за размером не следит.

7. **На карточке pub.dev не будет галереи скриншотов.** `screenshots/`
   закрыт `.pubignore`, поля `screenshots:` в `pubspec.yaml` нет. Картинки
   README отрисуются через `repository`, но пакет, который весь про вид
   вывода, останется без превью.

   **Вердикт (2026-08-23): открыто.** Решения владельца нет.
   Цена измерена: четыре кадра (`quick_start_1` 248 КБ, `data_1` 52,
   `loggable_1` 72, `trace_1` 64) поднимут архив со 184 КБ примерно до
   600.

8. **`docs/` не публикуется**, поэтому «Известные ограничения»
   (`architecture.md:356`) пользователю недоступны. Часть из них
   пользовательская — например висящее `login: ` при полном дропе свойств
   builder'а.

   **Вердикт (2026-08-23): закрыто, с поправкой.** `0f5b827`:
   новый раздел `## Known Limitations` в README. Пример в тексте находки
   оказался неточен — двоеточие не висит, за ним стоит пустая оболочка
   (`login: User()`, `login: {}`, `login: {₌₁ }`), и блок данных убирает
   только `LoggableMultiData`. Проверено запуском, `architecture.md`
   исправлен.

## Проверенные не-находки

- **Классы `logger_builder` на pub.dev документированы** — см. снятую
  находку 2. Урок общий: состояние API-справочника проверять на
  `pub.dev/documentation/<пакет>/latest/`, а не локальным `dart doc`.

- `MultiPublisher([...])` в форме из README (§8, присваивание в
  `log.publisher`) **компилируется и работает** — вывод параметра типа
  берётся из контекста присваивания. Отдельно от присваивания
  (`print(MultiPublisher([...]))`) вывод падает на `Object?`, но такой формы
  в README нет.
- `flutter_team_logger` на pub.dev существует (HTTP 200) — ссылка живая.
