# Взгляд глазами пользователя (2026-08-23)

Состояние на 2026-08-23. Ревью не по коду, а по пути пользователя: карточка
на pub.dev → README → первый `dart run` → справочник API. Всё, что помечено
«проверено», проверено запуском, а не рассуждением.

## Как проверялось

Отдельный пакет вне репозитория (`scratchpad/newuser`), зависимость
`team_logger` по `path:`, чистый `dart pub get`. API-справочник — `dart doc`
в отдельный каталог, поиск по `index.json` и по странице библиотеки. Архив —
`dart pub publish --dry-run`.

## Что хорошо

- README (2104 строки, 11 разделов, оглавление, 43 воспроизводимых кадра) —
  сильно выше среднего по pub.dev.
- CHANGELOG написан прозой, с причиной изменения и пометками
  `[breaking changes]`.
- Честность там, где обычно молчат: size settings названы rotation/retention
  targets, а не hard caps (README:1760); `output` синхронный и почему;
  «один вызов на строку, не на лог»; iOS-баг со ссылкой на upstream.
- Раздел про ленивость точно объясняет, что публикаторные фильтры
  срабатывают уже после вычисления замыкания.
- Полы зависимостей в `pubspec.yaml` прокомментированы причиной (пины
  Flutter 3.27), а не просто проставлены.
- `dart pub publish --dry-run`: 0 предупреждений, 183 КБ.

## Что плохо (проверено)

1. **Нет пути «просто запустить».** `Logger('app').i('hi')` не печатает
   ничего и ни на что не жалуется: уровень по умолчанию `Levels.off`
   (`logger_builder`, `custom_logger.dart:35`) **и** publisher не задан —
   два молчаливых затвора сразу. `ConsoleLogPrinter` требует `rows:`,
   `LogRow` требует `maxLength`. Минимальная рабочая конфигурация —
   `ConsoleLogPrinter(rows: const [LogRow.singleLine(children: [LogMessage()])])`
   — в README не встречается: Quick Start сразу даёт ~25 строк layout'а.

2. **~~Реэкспорт `logger_builder` не попадает в API-справочник~~ — снято
   2026-08-23, находка была неверна.** Проверялась на локальном `dart doc`,
   где `MultiPublisher` и соседи действительно отсутствуют. На pub.dev они
   документированы полноценно: у `MultiPublisher` своя страница
   `team_logger/MultiPublisher-class.html` с параметрами типа и описанием,
   класс стоит в списке классов библиотеки `team_logger`. Локальный
   `dart doc` не разрешает элементы зависимости так, как dartdoc на pub.dev,
   и выводить из него состояние справочника нельзя.

   Остаётся только та часть, что перечислена ниже в «непонятно»: имя
   `logger_builder` в README не встречается ни разу, поэтому не объяснено,
   откуда берутся `MultiPublisher` и `TransformPublisher` из примеров §8 и
   §10. Найти их пользователь может — понять, что это чужой пакет, нет.

3. **`CustomLogPublisher` назван «the seam for anything else»
   (README:427) — и всё.** Ни раздела «свой publisher», ни примера отправки
   в бэкенд/Sentry. Для библиотеки «для больших команд» это вопрос номер
   два после «как включить».

4. **Ничего про релизные сборки.** В README нет ни `kDebugMode`, ни «как
   выключить в проде», ни цены выключенного лога — при том что
   `logger_builder` продаёт себя строкой «good performance when disabled».

5. **Строки добиваются пробелами до `maxLength`.** Проверено: `maxLength: 60`
   + `noColors` → `short` и 55 пробелов до конца строки. В консоли это
   нужно (фон, правый `tail`), при перенаправлении в файл или агрегатор —
   хвостовой мусор. Выход — `LogRow.singleLine`, но об этом нигде не сказано.

6. **Ширина терминала не определяется автоматически.** `maxLength` всегда
   руками; `stdout.terminalColumns` не используется. `team_logger_io.dart`
   уже существует — место для такого хелпера есть.

7. **На карточке pub.dev не будет галереи скриншотов.** `screenshots/`
   закрыт `.pubignore`, поля `screenshots:` в `pubspec.yaml` нет. Картинки
   README отрисуются через `repository`, но пакет, который весь про вид
   вывода, останется без превью.

8. **`docs/` не публикуется**, поэтому «Известные ограничения»
   (`architecture.md:356`) пользователю недоступны. Часть из них
   пользовательская — например висящее `login: ` при полном дропе свойств
   builder'а.

## Что непонятно

- Почему `maxLength` обязателен в `LogRow` и запрещён в `LogRow.singleLine`.
  Что «без ограничения ширины» = `.singleLine`, из документации не следует.
- Пакет заявлен как «Dart & Flutter», есть бейдж Flutter 3.27 и скриншот
  Flutter-приложения — но раздела про Flutter нет: ни где инициализировать,
  ни что с hot reload, ни что с release. `flutter_team_logger` упомянут
  один раз на строке 1697.
- Отношение `team_logger` ↔ `logger_builder` не объяснено нигде.
- 0.7.0, три `[breaking changes]` в одном релизе, плана до 1.0 нет.

## Проверенные не-находки

- **Классы `logger_builder` на pub.dev документированы** — см. снятую
  находку 2. Урок общий: состояние API-справочника проверять на
  `pub.dev/documentation/<пакет>/latest/`, а не локальным `dart doc`.

- `MultiPublisher([...])` в форме из README (§8, присваивание в
  `log.publisher`) **компилируется и работает** — вывод параметра типа
  берётся из контекста присваивания. Отдельно от присваивания
  (`print(MultiPublisher([...]))`) вывод падает на `Object?`, но такой формы
  в README нет.
- `flutter_team_logger` на pub.dev существует (HTTP 200) — ссылка живая.
