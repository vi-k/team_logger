> **Состояние на 2026-08-21:** реализация, независимое ревью и проверки
> завершены; коммит впереди.
> **Что это:** исправление находки №5 полного ревью.
> **Связанные записи:** `2026-08-21[1]-project-review.md`,
> `2026-07-27[2]-file-log-storage-design.md`.

## Решение

`FileLogSessions.archiveTo()` удалён как breaking change и заменён на
`gzipTo()`. Новый метод последовательно передаёт `FileLogSession.read()` через
один `GZipCodec` в файловый sink. Выбранные сессии объединяются в заданном
порядке; каждая сохраняет собственную meta-строку, поэтому после распаковки
границы восстанавливаются без отдельных файлов внутри контейнера.

Если последняя строка одной сессии не заканчивается `\n`, перед первой строкой
следующей вставляется перевод строки. Это удерживает объединённый поток
валидным JSONL даже для вручную повреждённого чанка. Повторные meta-строки
внутри одной сессии по-прежнему удаляет `FileLogSession.read()`.

В реализации нет `BytesBuilder`, `Archive`, `ArchiveFile.bytes` и полного
output buffer. Память ограничена I/O- и compression-буферами и не зависит от
суммарного размера выбранных сессий. Пакет `archive`, больше нигде не
использовавшийся, удалён из зависимостей.

Target проверяется до `openWrite()`: если это выбранный chunk либо его
symlink/hardlink-алиас, `gzipTo()` возвращает `ArgumentError`, не меняя
источник. При ошибке чтения сохраняются исходная ошибка и stack trace;
вторичная ошибка закрытия output sink их не маскирует.

## TDD и измерение

Четыре теста сначала не компилировались ровно из-за отсутствующего `gzipTo()`.
После минимальной потоковой реализации все 23 теста `FileLogSessions` стали
зелёными:

- порядок сессий и meta-строка каждой;
- выбор подмножества и перезапись существующего target;
- сохранение no-follow защиты при подмене чанка symlink'ом;
- разделяющий `\n` после сессии без финального перевода строки.

Независимое ревью затем воспроизвело три дополнительных дефекта:

- поздний чанк без `LF` возвращался одним блоком размером со весь файл;
- target, равный выбранному чанку или symlink на него, успешно обнулял
  исходный лог;
- недоступный source chunk давал наружу вторичную `File closed` для target
  вместо исходной `PathAccessException`.

Каждое исправление прошло отдельный RED–GREEN цикл. Распознавание meta теперь
держит только короткий совпавший префикс, прямой и symlink-алиасы закреплены
отдельными тестами с проверкой сохранности source; hardlink закреплён ещё одним
POSIX-тестом, а permission-тест проверяет путь первичной ошибки. Весь файл —
28/28.

Повторное ревью нашло ещё одну комбинацию поддержанных сценариев: после
`list()` chunk заменён symlink'ом на victim, а его прежний snapshot path передан
как target. Проверка regular-file type пропускала source, после чего запись
обнуляла victim через symlink. Новый тест сначала завершался без ошибки и
менял victim; после исправления он зелёный. Теперь нормализованный абсолютный
target path сначала сравнивается со всеми snapshot chunk paths независимо от
их текущего типа, а filesystem identity остаётся вторым слоем для алиасов с
другим именем. Весь файл — 29/29.

Отдельный временный stress-probe создал четыре сессии по 32 МБ и запустил
экспорт 128 МБ под `--old_gen_heap_size=32`. Экспорт завершился: GZIP занял
130 633 байта, пиковый прирост RSS — 5 406 720 байт. Probe и его временные
данные удалены.

После независимого ревью probe повторён на опасной ветке reader: поздний
chunk размером 134 217 728 байт начинался с meta-префикса и не содержал `LF`.
Под тем же old-gen heap 32 МБ экспорт завершился; GZIP занял 63 байта, пиковый
прирост RSS — 8 306 688 байт. Это проверяет, что skip-state не накапливает
длинную meta-строку. Повторный probe и данные также удалены.
