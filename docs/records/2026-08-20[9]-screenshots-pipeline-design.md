# Конвейер скриншотов

## Что не так сейчас

В README 42 картинки из `screenshots/` (плюс одна сирота, на которую он не
ссылается). Из них 41 — ANSI-вывод пакета, одна
(`flutter_team_logger.png`) — снимок Flutter-приложения.

Ни одна из 41 не воспроизводится тем кодом, что лежит в репозитории.
Съёмка была ручной: владелец брал файл группы, комментировал лишнее,
**раскомментировал нужное** (в `trace.dart` подпись к `trace_4` — розовая
скобка «lazy-4, not lazy-6» — лежит закомментированной прямо сейчас),
добавлял логгеру тег и снимал кадр. Поэтому картинки — источник истины, а
код — материал, из которого они набирались.

Следствия, с которыми приходится жить:

- изменение в пакете, меняющее вывод, не видно, пока кто-то не сверит 42
  картинки глазами;
- пересъёмка одного кадра требует помнить, что именно в нём было
  закомментировано;
- проверки «картинки соответствуют коду» не существует.

## Решения владельца

1. **Время на кадрах — шагающий фиксированный `clock`.** Кадр исполняется
   внутри `withClock` с часами, стартующими в фиксированной точке и
   шагающими на десятки миллисекунд. Вывод выглядит как настоящий прогон,
   но пересъёмка даёт тот же результат.
2. **Заход — пилот на одной группе.** Конвейер собирается целиком и
   прогоняется на `trace` (четыре кадра). Остальные семь групп — потом.
3. **Тег `#log` остаётся и прописывается в коде.** `init_log.dart` и
   `default_log.dart` получают `tags: {'log'}`, после чего код
   воспроизводит то, что на картинках.

## Устройство

### Кадр — именованная функция

Файл группы объявляет карту кадров и отдаёт её общей точке входа:

```dart
// example/bin/readme_examples/trace.dart
final frames = <String, Frame>{
  'trace_1': _searchTrace,
  'trace_2': _traceIdConfigurations,
  'trace_3': _traceIdWithSuffix,
  'trace_4': _laziness,
};

void main(List<String> args) => runFrames(frames, args);
```

Имя кадра — имя PNG без расширения. Никакого отдельного манифеста: он
дублировал бы то, что уже есть в коде, и разъезжался бы с ним.

### `runFrames` — общая точка входа

```dart
// example/lib/readme_examples/frames.dart
import 'dart:async';
import 'dart:io';

import 'package:clock/clock.dart';

typedef Frame = FutureOr<void> Function();

/// Точка входа файла-группы.
///
/// - `--list` — печатает имена кадров, по одному на строку;
/// - `<имя кадра>` — исполняет один кадр под фиксированными часами;
/// - без аргументов — исполняет все кадры подряд, с заголовками (так файл
///   ведёт себя сегодня, и таким его можно просто запустить и посмотреть).
Future<void> runFrames(Map<String, Frame> frames, List<String> args) async {
  if (args.contains('--list')) {
    frames.keys.forEach(print);

    return;
  }

  if (args.isEmpty) {
    for (final MapEntry(key: name, value: frame) in frames.entries) {
      print('----- $name -----');
      await frame();
    }

    return;
  }

  final name = args.first;
  final frame = frames[name];
  if (frame == null) {
    stderr.writeln('Unknown frame: $name. Known: ${frames.keys.join(', ')}');
    exitCode = 2;

    return;
  }

  await withClock(_frameClock(), frame);
}

/// Часы кадра: старт в фиксированной точке, шаг 37 мс на каждое обращение.
///
/// Время в логах растёт, как в настоящем прогоне, но пересъёмка даёт тот
/// же вывод — поэтому `.ansi` рядом с картинкой не «дрожит», а `--check`
/// может сравнивать его как текст.
Clock _frameClock() {
  var tick = 0;
  final base = DateTime(2026, 3, 14, 9, 26, 53, 589);

  return Clock(() => base.add(Duration(milliseconds: 37 * tick++)));
}
```

`example/pubspec.yaml` получает зависимость `clock: ^1.1.1` — тот же floor,
что у пакета.

Шаг привязан к **обращению** к часам, а не к логу: если пакет спросит
`clock.now()` дважды на один лог, соседние строки разойдутся не на 37 мс, а
на 74. Воспроизводимости это не мешает — важно, что от прогона к прогону
результат один и тот же, — но подбирать «красивый» шаг надо по факту, глядя
на кадр, а не расчётом.

### Кадр — отдельный процесс, и это не оптимизация

`Log.num` — счётчик, глобальный на изолят (`num = ++lastNum`), и счётчики
`TraceId.auto` тоже. На картинках это видно прямо: `trace_1` и `trace_2`
обе начинаются с `(1)`, а `trace_2` показывает `{group-1}` — то есть
процесс был свежий. Поэтому скрипт запускает `dart run <файл> <кадр>`
отдельно на каждый кадр. Режим «без аргументов» гоняет всё в одном
процессе — для человека, не для съёмки; нумерация там сквозная, и это
нормально.

### Рядом с PNG лежит `.ansi`

Скрипт пишет два файла на кадр: `screenshots/trace_1.ansi` и
`screenshots/trace_1.png`.

Смысл в двух вещах. Первая: `git diff` на текстовом `.ansi` читаем — видно,
какая строка лога изменилась, — тогда как на PNG это непрозрачный блоб.
Вторая: проверка свежести сравнивает `.ansi`, а не картинки, и потому не
зависит от машины и версии шрифтов; побайтовое сравнение PNG зависело бы.

`screenshots/` уже в `.pubignore`, так что в pub-архив `.ansi` не поедет.

### `scripts/screenshots.sh`

Новый скрипт поверх существующего `ansi_screenshot.sh`:

```
scripts/screenshots.sh                 # пересобрать все переведённые группы
scripts/screenshots.sh --only trace    # одну группу
scripts/screenshots.sh --check         # сравнить .ansi, ничего не писать
```

Что делает:

1. обходит `example/bin/readme_examples/*.dart`;
2. спрашивает у каждого `dart run <файл> --list`; файл, который не отвечает
   списком (ещё не переведён на кадры), **пропускается с предупреждением**
   — во время поэтапного перевода это норма, а не ошибка;
3. на каждый кадр: `dart run <файл> <кадр>` с перенаправлением в
   `<кадр>.ansi`, затем `ansi_screenshot.sh --input <кадр>.ansi --output
   <кадр>.png`;
4. в конце сообщает про PNG в `screenshots/`, которые не заявил ни один
   кадр, кроме известного исключения `flutter_team_logger.png`.

Захват вывода — **простым перенаправлением, без `script(1)`**. Pty здесь не
нужен: принтер отдаёт ANSI и в пайп. `script(1)` в этой сессии дважды
подвёл — то требует tty, которого нет, то дописывает `^D` в начало файла,
и его приходится вырезать.

`--check` рендерит `.ansi` во временный каталог и сравнивает с
`screenshots/*.ansi`; при расхождении печатает `diff` и выходит с кодом 1.

## Детали, которые видно только в картинках

Их легко потерять при реконструкции, поэтому они здесь:

- **Подписи.** `trace_4.png` содержит нарисованную розовую скобку с текстом
  «lazy-4, not lazy-6» — она есть в коде, но закомментирована. В кадре
  она раскомментирована и печатается: кадр — источник истины, значит всё,
  что на картинке, должно печататься его кодом.
- **Тег `#log`** в правом углу каждого кадра — от `LogTags()` в хвосте
  раскладки. Появляется после `tags: {'log'}` в `init_log`/`default_log`.
- **Счётчики стартуют с единицы** — следствие процесса на кадр.
- **Уровень логгера мутируется внутри кадра** (`trace_4` переставляет
  `log.level` на `warning` посередине). В отдельном процессе это
  безопасно; в режиме «без аргументов» — нет, но этот режим для человека.

## Пилот: группа `trace`

Четыре секции в сегодняшнем `trace.dart` один в один ложатся на четыре
картинки:

| кадр | что показывает | что на картинке |
| --- | --- | --- |
| `trace_1` | `log.trace` вокруг двух логов | `(1)`–`(2)`, `{search-1}` |
| `trace_2` | `TraceId.global/auto/manual` | `(1)`–`(3)`, `{1}`, `{group-1}`, `{group-123}` |
| `trace_3` | `withSuffix` при повторах запроса | `(1)`–`(4)`, `{request-1}`…`{request-1.4}` |
| `trace_4` | ленивость нумерации | `(1)`–`(4)`, `{lazy-1}`…`{lazy-4}` плюс подпись |

Каждый кадр восстанавливается по своей картинке и сверяется с ней глазами.
Это реконструкция, а не разрезание: сегодняшний код их не воспроизводит.

Новые картинки будут отличаться от старых временем — оно станет
синтетическим и одинаковым от прогона к прогону. Это ожидаемо и есть цель.

## Что не входит

- Остальные семь групп (37 кадров) — следующим заходом, после того как
  пилот покажет, что конвейер годится.
- `README.md` не меняется: имена картинок те же.
- `flutter_team_logger.png` из конвейера исключён навсегда — это снимок
  Flutter-приложения, а не ANSI-вывода. Скрипт знает про него как про
  исключение и не считает сиротой.
- `quick_start3.png` — сирота, на которую README не ссылается; удаляется.
- Проверка свежести **не** добавляется в чеклист «Релиз» на этом этапе:
  пока переведена одна группа, ей нечего проверять целиком. Добавляется
  после перевода всех.
- `ansi_screenshot.sh` не переписывается: режим `--command` там остаётся
  для ручных снимков, конвейер просто им не пользуется.

## Проверки

- `dart analyze` в `example/` — чисто.
- `dart run bin/readme_examples/trace.dart --list` печатает четыре имени.
- `dart run bin/readme_examples/trace.dart trace_1` (и остальные три)
  печатают ровно то, что на соответствующей картинке.
- `dart run bin/readme_examples/trace.dart` без аргументов по-прежнему
  печатает всё подряд.
- `scripts/screenshots.sh --only trace` пересобирает четыре `.ansi` и
  четыре `.png`; повторный запуск не меняет ни одного байта в `.ansi`.
- `scripts/screenshots.sh --check` проходит.
- `scripts/screenshots.sh` целиком: семь непереведённых групп
  пропускаются с предупреждением, сироты названы.
- Остальные семь групп по-прежнему запускаются вручную и печатают то же,
  что раньше, — кроме тега `#log`, который теперь появится и у них.
