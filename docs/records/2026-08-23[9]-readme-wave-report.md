## Что проверено запуском, а не рассуждением

Каждый фрагмент кода из новых разделов компилировался и запускался в
отдельном пакете вне репозитория:

- голый `Logger('app').i(...)` действительно молчит;
- минимум из пяти строк печатает `hello`;
- `LogRow(maxLength: 60)` добивает строку пробелами до 60,
  `LogRow.singleLine` — нет;
- `package:team_logger/team_logger.dart` компилируется `dart compile js` —
  значит утверждение про web не выдумано;
- `TelemetryPublisher` из §12 и фабрика `CustomLogPublisher<Log>(...)`
  работают в том виде, в каком записаны.

Побочно выяснилось: у `Logger.publisher` есть сеттер и нет геттера.

## Две поправки в `docs/architecture.md`

Собираясь перенести «Известные ограничения» в README, проверил их — два
пункта разошлись с реальностью:

1. **«Висящее двоеточие `login: `» — неточно.** Двоеточие не висит, за ним
   стоит пустая оболочка, и вид её зависит от формы данных: `login: User()`,
   `login: {}`, `login: Object()`, `login: {₌₁ }`. Блок данных убирает
   только `LoggableMultiData` — он один и печатает `login`. Таблица занесена
   в `architecture.md`, в README пункт переписан по факту.
2. **«Билдеры не передают config корневой замене» — больше не так.**
   `mapBuilder(config:)`, `builder(config:)`, `LoggableMultiData(config:)` и
   `Loggable.from(config:)` дают одинаковый `[₌₃ ₀:1, …]`: config доходит,
   `units` снимаются. Пункт удалён.

Урок тот же, что и со снятой находкой 2 ревью: список ограничений стареет
молча. Переписывая его, проверять, а не переносить.
