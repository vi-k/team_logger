## Что сейчас

Вся раскладка меряет текст в **UTF-16 code units**. Источник —
`ansi.Parser.length` и `ansi.Parser.substring(start, maxLength:)` из
`ansi_escape_codes` 4.0.1; сам пакет это честно документирует: «String length
without ANSI escape codes, in UTF-16 code units. … Graphemes are not counted».

Места, где это используется:

- `lib/src/printer/log_block.dart:40` и `:109` — ширина бокса как максимум по
  строкам;
- `:118`, `:130`, `:143`, `:148`, `:158` — решение о переносе и сама нарезка;
- `lib/src/printer/extensions.dart` — `applyConstraints` (добивка пробелами,
  обрезка), `terminatedSubstring` (обрезка с многоточием);
- `lib/src/printer/surrogates.dart` — заплатка `fixDanglingSurrogates`,
  которая после разреза по code units меняет повисшую половину суррогатной
  пары на пробел.

Публично это обещано в README: «`maxLength` limits the width of the log
message».

## Что ломается

Code unit — не колонка терминала. Расходятся три класса символов:

| Вход | Code units | Колонок в терминале |
| --- | --- | --- |
| `世` (CJK) | 1 | 2 |
| `e` + U+0301 (combining acute) | 2 | 1 |
| `👨‍👩‍👧` (ZWJ-последовательность) | 8 | 2 |
| `𝄞` (вне BMP, без ZWJ) | 2 | 1 или 2 |

Следствия ровно те, что назвало ревью: строка с CJK выходит за заявленную
ширину примерно вдвое, строка с диакритикой получает лишние переносы,
эмодзи-последовательность рвётся посередине. Выравнивание `tail` (теги у
правого края) съезжает на международном вводе, то есть на обычном, а не
экзотическом.

`fixDanglingSurrogates` — симптоматическое лечение одного частного случая:
она чинит разрезанную суррогатную пару, но ничего не знает ни о кластерах, ни
о ширине.

## Модель

Одна модель ширины на все операции — измерение, добивку, обрезку, перенос и
выравнивание.

**Единица — экранная колонка.** Ширина строки есть сумма ширин её графемных
кластеров.

**Ширина кластера** определяется его первым code point'ом (base):

- `0` — combining marks (категории `Mn`, `Me`), zero-width символы (U+200B…
  U+200D, U+FEFF), variation selectors;
- `2` — East Asian Wide (`W`) и Fullwidth (`F`) по UAX #11, плюс диапазоны
  emoji presentation;
- `1` — всё остальное.

Управляющие символы в раскладку не попадают: `ControlCodeFormatter` уже
превратил их в видимый текст, а ANSI-коды снимает парсер.

**Нарезка идёт по границам кластеров.** Это делает
`fixDanglingSurrogates` ненужной по построению: разрезать пару больше нечем.
Заплатку оставляем как страховку на чужой вход, но собственная нарезка на неё
не опирается.

**Кластер не делится.** Если очередной кластер не влезает в остаток бюджета,
он целиком переносится на следующую строку. Поэтому строка может оказаться на
колонку уже заявленной ширины — это правильное поведение: широкий символ,
разрезанный пополам, не имеет смысла.

## Как это ложится на существующий парсер

Апстрим менять не нужно, и это главный вывод разбора.

`ansi.Parser.substring(start, maxLength:)` считает позиции **в code units
plain-текста** — то есть в тех же единицах, в которых мы и так работаем.
Значит достаточно надстройки, которая переводит бюджет колонок в число code
units:

1. `plain = input.ansiRemoveEscapeCodes()` — публичный API пакета;
2. пройти `plain` кластерами, накапливая пары «сколько колонок / сколько code
   units»;
3. `displayWidth(input)` — сумма ширин кластеров;
4. `codeUnitsForColumns(plain, startCU, columns)` — сколько code units
   занимают кластеры, целиком влезающие в `columns` колонок начиная с
   `startCU`.

Дальше вся текущая механика нарезки работает как была: в `parser.substring`
уходит посчитанное число code units. `ansi_escape_codes` — пакет того же
владельца, и перенос модели ширины туда выглядел бы логично, но не требуется:
парсер уже отдаёт всё нужное.

## Что меняется публично

Ломающее изменение поведения без изменения сигнатур: `LogRow.maxLength`,
`LogConstraints`, выравнивание и `tail` начинают считать колонки вместо code
units. Для вывода из ASCII не меняется ничего — там колонка и code unit
совпадают. Для логов с CJK, диакритикой и эмодзи меняется раскладка, и в этом
весь смысл правки. README и dartdoc должны сказать «колонки терминала», а не
«длина».

## Открытый вопрос к владельцу

Графемная сегментация. Полный UAX #29 руками — отдельная работа и постоянный
источник расхождений с Unicode; пакет `characters` делает ровно это.

- **Вариант A — взять `characters`.** Плюс: корректные кластеры без
  собственного кода, пакет от dart.dev. Минус: первая рантайм-зависимость,
  добавленная после волны, в которой из графа выпилили `format` и `intl`.
  **Важное ограничение:** констрейнт обязан быть `^1.3.0`, а не `^1.4.0` —
  Flutter 3.27 пинит `characters` 1.3.0, и это ровно та ловушка, из-за
  которой `format` ^1.6.0 ломал установку в локализованное Flutter-приложение
  (см. CHANGELOG 0.7.0). С `^1.3.0` матрица Flutter остаётся зелёной, а в
  Flutter-приложении зависимость и так уже есть.
- **Вариант B — обойтись без зависимости.** Своё правило «кластер
  продолжается, пока следующий code point — combining mark, ZWJ, variation
  selector или парный regional indicator». Покрывает все три случая, которые
  назвало ревью, и ноль новых зависимостей. Минус: это не UAX #29, на редких
  последовательностях будет расходиться с терминалом.
- **Вариант C — не делать.** Оставить как есть и задокументировать, как
  сделали с находкой №10. Пункт уже стоит в «Известных ограничениях».

Таблица East Asian Width нужна в любом из вариантов A и B и встраивается в
пакет как данные — внешнего источника для неё нет.

**Рекомендация агента была вариант B** (ноль зависимостей). **Решение
владельца 2026-08-22 — вариант A:** берём `characters` с констрейнтом
`^1.3.0`. Значит кластеры считает UAX #29, а не собственное приближение, и
расхождений с терминалом на редких последовательностях не будет.

Из этого следуют два обязательства реализации:

1. констрейнт ровно `^1.3.0` — `^1.4.0` снимет Flutter 3.27 с матрицы;
2. матрицу Flutter переснять после правки `dependencies` — это требование
   handoff'а на любое изменение графа.

## План тестов (после решения)

- ширина: `世` → 2, `e`+U+0301 → 1, ZWJ-семья → 2, ASCII → 1;
- обрезка: CJK-строка не выходит за `maxLength`; кластер не делится;
- перенос: строка с диакритикой не получает лишних переносов;
- эмодзи на границе обрезки не разрывается;
- выравнивание `tail` не съезжает при CJK в сообщении;
- регрессия на `fixDanglingSurrogates`: чужой вход с повисшей половиной
  по-прежнему чинится;
- существующие тесты суррогатных пар в `console_log_printer_test.dart`
  остаются зелёными.
