## Результат

Находка не является новым дефектом реализации. Утверждённая перед
реализацией спецификация требует сохранять каждую JSONL-запись целиком:
строка длиннее `maxChunkSize` не разрезается. Самый новый чанк также не
удаляется, чтобы не потерять свежие логи. Этот контракт реализован в
`12edda6` и закреплён тестом с записью, превышающей `maxChunkSize` и
`maxSessionSize`.

Недочётом оказалась публичная формулировка «лимиты», допускавшая прочтение как
жёсткие потолки. README, dartdoc, архитектура и CHANGELOG теперь явно
разделяют:

- `maxChunkSize` — целевой размер, после которого ротируется чанк;
- `maxSessionSize` — целевой retained-размер сессии;
- `maxTotalSize` — startup retention budget для всех сессий.

Одна атомарная запись может превысить все три настройки. Приложение, которому
нужен жёсткий предел расхода диска, должно до публикации ограничивать размер
session metadata, сообщений, ошибок, стеков и рендеримых данных.
