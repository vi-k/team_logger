### №14 — `zonedTags()` отдавал изменяемое состояние зоны

`zonedTraceIds()` заворачивал список в `UnmodifiableListView`, симметричный
`zonedTags()` возвращал сам `Set` зоны. Любой читатель статического геттера
мог добавить тег и молча перетегировать все последующие логи той же async
zone. Теперь `UnmodifiableSetView`; попытка `add` даёт `UnsupportedError`.

Заодно характеризован соседний инвариант, который уже работал: `trace()`
копирует переданное множество, поэтому вызывающий не сохраняет пишущую ручку
на состояние зоны.

Ломающее для кода, который мутировал результат геттера.

### №13 — изменяемые настройки против кэшей по identity

Половина находки устарела до начала работ, и это стоило проверить до, а не
после починки. Кэша regex BBCode по identity темы больше нет: переписывание
парсера по находке №1 заменило backtracking-regex однопроходным scanner'ом,
который читает набор тегов из темы на каждый вызов. Тег, добавленный в
изменяемую `messageStyles` после первой печати, применяется со следующего
рендера; закреплено тестом. Кэш уровней темы держит `LogTheme._(this, level)`
в `Expando` — ссылку на тему, а не снимок настроек, так что и он мутацию
видит.

Актуальной была вторая половина. `ConsoleLogPrinter.output` изменяем, а
`_printers` кэширует `StackedPrinter` на пару `(isActive, level)` с
захваченным при создании sink'ом. Подмена `output` после первой печати уходила
в старый sink для уже напечатанных уровней и в новый — для ещё не
встречавшихся: применялась частично и по истории вызовов, то есть хуже всего
там, где поле полезнее всего, — при подмене sink'а в тесте. Исправлено без
сброса кэша: принтер уровня пишет через метод, читающий поле при каждом
вызове.

### №11 — корневая sanitizer-замена теряла config билдера

README обещает, что значение, поставленное правилом на место корня,
печатается настройками контейнера. Умел это только `LoggableMultiData`.
`Loggable.builder()` и `mapBuilder()` держат config в приватном поле
подкласса, и общий корневой путь его не видел.

Воспроизведение до правки на четырёх контейнерах сразу: при
`collectionMaxCount: 1` и замене корня на `[1, 2, 3]` `LoggableMultiData` и
`LoggableWrapper` печатали сокращённый список, а `builder` и `mapBuilder` —
полный, и в строке, и в `objectToJson()`.

Исправлено единой точкой вместо второй ветки: `LoggableData` получил
библиотечно-приватный `_ownConfig`, билдеры его переопределяют,
`_rootConfig`/`_rootJsonConfig` спрашивают через общий `_containerConfig`.
`LoggableWrapper` туда намеренно не попал — он разворачивает себя до обхода;
это закреплено тестом, чтобы отсутствие ветки не выглядело пропуском.

### №15 — ширина считалась в UTF-16 code units

Самая тяжёлая, единственная со спекой:
`2026-08-22[3]-display-width-design.md`.

Главный вывод разбора: апстрим `ansi_escape_codes` менять не нужно.
`Parser.substring(start, maxLength:)` адресует позиции в code units
plain-текста, а `ansiRemoveEscapeCodes()` — публичный API того же пакета,
читающий тем же шаблоном. Достаточно надстройки, переводящей бюджет колонок в
число code units.

Появились два внутренних модуля: `display_width.dart` (таблицы UAX #11,
`displayWidth`, `ClusterIndex`) и `measured_line.dart` (парсер плюс индекс
кластеров). Вся раскладка — измерение, добивка, обрезка, перенос,
выравнивание tail — переведена на колонки.

`fixDanglingSurrogates` удалён: нарезка по границам кластеров не может
разрезать суррогатную пару, и заплатка стала мёртвым кодом. Два теста на
повисшие половины теперь проходят по построению.

Решение владельца — `characters ^1.3.0`. Констрейнт проверен негативной
пробой: `^1.4.0` роняет version solving на Flutter 3.27, и pub сам предлагает
понизить до `^1.3.0`.

Ломающее изменение поведения без изменения сигнатур: `LogRow.maxLength` и
выравнивания теперь считают колонки. ASCII-вывод не изменился.
