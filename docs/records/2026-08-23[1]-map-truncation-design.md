# Спека: обрезка `Map` лимитами коллекций

> **Состояние на 2026-08-23:** реализовано; отчёт —
> `2026-08-23[2]-map-truncation-report.md`. Владелец выбрал **вариант A** —
> счётчик по `collectionShowCount`, как у `List`/`Set`.
> **Что это:** устройство пункта бэклога «Обрезка `Map` лимитами коллекций —
> сейчас `Map` не ограничивается вообще».
> **Связанные записи:** `2026-08-22[9]-iterable-efficient-length-report.md`,
> `2026-08-22[6]-config-chain-report.md` (слои, в которые встанут лимиты).

## Что сейчас

`_mapToString` рендерит **все** записи и склеивает их запятыми. `_mapToJson`
кладёт в результат **все** пары. Ни `collectionMaxCount`, ни
`collectionMaxStringLength` до `Map` не доходят — их читают только
итерируемые ветки.

Это дыра в контроле размера лога, а не мелочь: список из тысячи элементов
свернётся по `collectionMaxCount`, а мапа из тысячи ключей уедет в лог
целиком — и в консоль, и в JSONL-файл. Приложение, которое положило в лог
разобранный JSON-ответ или заголовки запроса, ограничить его сегодня не
может ничем.

## Что предлагается

`Map` начинает подчиняться тем же двум лимитам, что и остальные коллекции:
`collectionMaxCount` — сколько записей печатать, `collectionMaxStringLength`
— сколько места занимать. Оба уже разрешаются цепочкой слоёв, так что
`Loggable.forceConfig` сможет поставить потолок, который место вызова не
снимет.

**Что сохраняется при обрезке — первые записи и последняя**, как у `List` и
`Set`. `Map` переобходима и упорядочена (`LinkedHashMap` хранит порядок
вставки), так что последняя запись доступна и осмысленна, а «первая и
последняя» уже знакомы читателю по спискам:

```
{a: 1, b: 2, …, e: 5}
```

**`collectionShowIndexes` к `Map` не относится** — у записей есть ключи, и
номера позиций им не нужны. Вопроса тут нет.

## Взаимодействие с санитайзером

Запись, которую правило отдало как `Sanitize.drop`, из вывода исчезает
целиком — так устроено сегодня и так остаётся. Отсюда два следствия, которые
надо зафиксировать явно:

1. **Лимит считает выжившие записи.** Иначе обрезка «первые три» после двух
   дропов напечатала бы одну запись из трёх — число на выходе не значило бы
   ничего.
2. **Заявленная длина — длина исходной `Map`.** У списка дроп оставляет
   маркер `<dropped>`, поэтому длина честна сама собой; у мапы записи
   исчезают, и исходная длина остаётся единственным следом того, что данные
   были урезаны не только лимитом.

## JSON

Прецедент уже есть и ему надо следовать. `listToJson` меняет форму при
обрезке: целый список — просто массив `[a, b, c, d]`, обрезанный —
`{":k": "list", ":l": 4, ":v": [a, d]}`.

Так же и здесь: целая `Map` остаётся обычным JSON-объектом (сегодняшняя
форма, ничего не ломается), обрезанная становится

```json
{":k": "map", ":l": 5, ":v": {"a": 1, "b": 2, "e": 5}}
```

Служебные ключи не могут столкнуться с пользовательскими: ключи,
начинающиеся с `:`, экранируются (`::k`).

## Открытый вопрос к владельцу

**Показывать ли у `Map` количество записей.** Это единственная развилка, и
она видна в каждом логе с мапой.

- **Вариант A — как у `List`/`Set`, по настройке `collectionShowCount`.**
  Единообразно: настройка называется `collectionShowCount`, и коллекция
  сообщает свой размер, когда её об этом просят. `{₌₅ a: 1, b: 2, …, e: 5}`.
  Цена: **вид меняется у всех мапп, а не только у обрезанных**, и кадры
  README придётся переснять (мапы есть в `quick_start` и `data`). Кому не
  надо — ставит `collectionShowCount: false`.
- **Вариант B — количество только при обрезке.** Пока лимит не сработал,
  вывод байт в байт сегодняшний, кадры не трогаем. Обрезанная мапа честно
  говорит, сколько записей было. Цена: `collectionShowCount` для `Map`
  работает не так, как для списков, и это придётся объяснять.
- **Вариант C — количество не показывать никогда**, только `…`. Меньше всего
  изменений, но обрезанная мапа перестаёт сообщать, сколько данных скрыто, —
  а это ровно то, ради чего лимит и ставят.

**Рекомендую вариант A.** Настройка одна на все коллекции, и разное
поведение для `Map` пришлось бы держать в голове при каждом чтении конфига.
0.7.0 не выпущена, пересъёмка кадров воспроизводима и стоит одной команды, а
`collectionShowCount: false` остаётся для тех, кому размер мапы не нужен.
