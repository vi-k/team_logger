## Что берём

Владелец 2026-08-22: «бери все low». После закрытия №10 (принята и
задокументирована) Medium-находок не осталось; открыты пять Low.

Каждая находка — отдельный цикл: RED-тест, починка, GREEN, коммит. Никаких
сборных коммитов: находки независимы, и смешивать их значит терять
возможность откатить одну.

## Проверка актуальности перед началом

Ревью писалось на срезе `a175dd7`, после него приехали девять исправлений.
Сверено на текущем дереве:

- **№11** — актуальна. `Loggable._rootConfig()`/`_rootJsonConfig()` знают
  только `LoggableMultiData`; `_LoggableBuilder` и `_LoggableMapBuilder`
  держат свой `config` приватным полем, общий код его не видит.
- **№13** — актуальна наполовину. Часть про кэш regex BBCode по identity
  темы **устарела**: переписывание парсера по находке №1 убрало кэш совсем,
  `BbCodeFormatter.call` собирает набор тегов из темы на каждый вызов. Часть
  про `ConsoleLogPrinter.output` актуальна: поле изменяемое, а `_printers`
  кэширует `StackedPrinter` с захваченным старым `output` на пару
  `(isActive, level)`.
- **№14** — актуальна. `Logger.zonedTags()` отдаёт сам `Set` зоны, тогда как
  `zonedTraceIds()` заворачивает список в `UnmodifiableListView`.
- **№15** — актуальна. Ширина считается по UTF-16 code units.
- **№16** — актуальна целиком: `LogElement` в README (три места) и в
  `docs/architecture.md`, `file:///Users/...` в ссылке на LICENSE, описание
  ручного комментирования кадров в `example/README.md`, противоречие внутри
  0.7.0 в CHANGELOG (`format` сначала требуется, потом объявлен убранным),
  предупреждение `dart doc --validate-links` на `[a, b, c, d]`.

## Порядок

От самостоятельных и дешёвых к тому, что требует спеки. Так первые находки
закрываются сразу, а самая тяжёлая не блокирует остальные.

### 1. №14 — `zonedTags()` отдаёт изменяемое состояние зоны

Симметрия с `zonedTraceIds()`. Возвращать `UnmodifiableSetView`.

- RED: внутри `trace(..., tags: {'original'})` вызвать
  `Logger.zonedTags().add('injected')` — сейчас проходит и меняет теги всех
  последующих логов зоны; ожидаем `UnsupportedError`.
- RED: тег, добавленный в исходный `Set` снаружи после входа в зону, не
  должен просачиваться (проверить, копируется ли множество при входе).
- Ломающее для того, кто мутировал результат getter'а, — пункт в CHANGELOG
  с пометкой `[breaking changes]`.

### 2. №16 — документация разошлась с API

Механическая синхронизация, но проверяемая.

- `LogElement` → `LogBlock` в `README.md` (три места) и
  `docs/architecture.md`; сверить, что базовый тип действительно
  `LogBlock` (`lib/src/printer/log_block.dart:15`).
- LICENSE: `file:///Users/...` → относительная ссылка `LICENSE`.
- `example/README.md`: описание `bin/readme_examples/` переписать под
  фактический конвейер кадров (`runFrames`, `--list`, `scripts/screenshots.sh`),
  а не под ручное комментирование; там же «archiving» → gzip, потому что
  пример зовёт `gzipTo`.
- CHANGELOG: два соседних пункта про `format` внутри 0.7.0 противоречат друг
  другу. Переписать как одну историю итогового решения: зависимость
  поднималась, а затем ушла из пакета совсем.
- dartdoc `loggable.dart:1400`: `[a, b, c, d]` вне блока кода читается как
  doc-reference. Экранировать.
- Критерий готовности: `dart doc --validate-links` — **0 предупреждений**
  (сейчас одно).

### 3. №13 — изменяемые настройки против кэшей по identity

- Устаревшую часть про BBCode-кэш зафиксировать в вердикте находки, а не
  «чинить» несуществующее.
- `ConsoleLogPrinter.output`: оставить настраиваемым, но сделать
  присваивание согласованным — setter сбрасывает `_printers`, чтобы уже
  созданные принтеры не держали старый sink.
- Проверить, копируются ли `messageStyles`/`tags` темы при построении; если
  нет — заворачивать в unmodifiable, чтобы «поменял map после первой печати»
  не давало вывод, зависящий от истории вызовов.
- RED: напечатать лог, подменить `output`, напечатать тем же уровнем — сейчас
  строка уходит в старый sink.

### 4. №11 — корневая sanitizer-замена теряет config контейнера

- Дать контейнерам единый внутренний доступ к собственному config:
  библиотечно-приватный геттер на `LoggableData` (`null` по умолчанию),
  переопределённый в `_LoggableBuilder` и `_LoggableMapBuilder`;
  `_rootConfig`/`_rootJsonConfig` спрашивают его наравне с
  `LoggableMultiData`.
- Проверить `LoggableWrapper`: он разворачивает себя до обхода и, похоже,
  протаскивает config сам — подтвердить пробой, а не предположением.
- RED: симметричные string/JSON/e2e тесты для `builder`, `mapBuilder` и
  `multiData` — замена корня на `[1, 2, 3]` при `collectionMaxCount: 1`
  обязана печататься сокращённой.

### 5. №15 — ширина не соответствует экранной

Самая тяжёлая и единственная, которой нужна спека до кода: меняется
публичный смысл `LogRow.maxLength` и всех выравниваний.

- Отдельная запись `design` с моделью ширины: grapheme clusters вместо code
  units, wcwidth-подобная ширина колонки (CJK и emoji — две, combining —
  ноль), одна модель на все операции slicing/alignment.
- Открытый вопрос к владельцу — источник данных: тянуть `characters` ради
  grapheme clusters и встраивать таблицу East Asian Width, либо обойтись
  собственной таблицей без новой зависимости. Пакет держит зависимости
  узкими намеренно, поэтому решение не за агентом.
- Спрашивать владельца **после** того, как первые четыре находки закрыты, —
  чтобы вопрос не блокировал остальную работу.
- Тест-кейсы: CJK, combining mark, ZWJ emoji, суррогатные пары на границе
  обрезки, выравнивание tail.
