# Установка во Flutter-приложение

## Задача

Владелец попросил обновить все зависимости, но так, чтобы пакет ставился во
Flutter-приложение. Минимальной линией выбран Flutter 3.27 — первая с
Dart 3.6, то есть ровно тот floor, который пакет и объявляет.

## Что мешало

Flutter пиннит часть пакетов **точной** версией из своего SDK. Floor выше
такого пина — не «возьмём посвежее», а отказ version solving. Пины:

| пакет | Flutter 3.27 | Flutter 3.29 |
| --- | --- | --- |
| `meta` | 1.15.0 | 1.16.0 |
| `clock` | 1.1.1 | 1.1.2 |
| `stack_trace` | 1.12.0 | 1.12.1 |
| `characters` | 1.3.0 | 1.4.0 |
| `intl` (через `flutter_localizations`) | 0.19.0 | 0.19.0 |

Наши floor'ы `meta ^1.16.0`, `clock ^1.1.2`, `stack_trace ^1.12.1` были
равны пинам 3.29 — то есть на 3.27/3.28 пакет не ставился вовсе, хотя
заявлял `sdk: ^3.6.0`. Понижены до пинов 3.27; ничего новее в коде не
используется (`clock.now()`, `Trace`, `@internal`/`@nonVirtual`/
`@visibleForTesting`).

Второй слой оказался глубже и важнее. `format` 1.6.0 тянет
`characters ^1.4.0` (3.27 пиннит 1.3.0) и `intl ^0.20.2`, тогда как
`flutter_localizations` пиннит `intl 0.19.0` и на 3.27, и на 3.29.
Проверено вживую: приложение с `flutter_localizations` на Flutter 3.29 не
могло взять пакет вообще — «team_logger from path depends on format ^1.6.0
which depends on intl ^0.20.2».

## Решение

`format: '>=1.5.2 <2.0.0'` вместо `^1.6.0`. Какая из двух версий попадёт в
приложение, решает его собственный SDK: на 3.27 — 1.5.2 с `intl 0.19.0`, на
свежих линиях — 1.6.0.

Обновить `format` до 4.0.0 нельзя без потери Flutter 3.27: 3.0.0 и 4.0.0
подняли свой floor до Dart `^3.7.2` (Flutter 3.29.2). Это было бы соблазнительно
— в 3.0.0 `intl` вынесен в отдельный пакет, и граф зависимостей приложения
избавился бы от него совсем, — но противоречит выбранной минимальной линии.
Пункт стоит держать в голове на будущее.

## Пробел в тестах, который это вскрыло

`intFormat`/`doubleFormat` не были покрыты вообще — ноль упоминаний в
тестах. То есть «тесты зелёные на 1.5.2, 1.6.0, 3.0.0 и 4.0.0» ничего не
доказывало: форматирование чисел просто не проверялось.

Добавлен `test/loggable/number_format_test.dart` — 23 теста на спецификации
`{:05d}`, `{:,d}`, `{:x}`, `{:.2f}`, `{:010.2f}`, `{:,.2f}`, `{:.3e}`,
`{:g}`, на units после значения и на округление. На 1.5.2 и 1.6.0 вывод
совпадает полностью. На 3.0.0/4.0.0 расходится ровно одно место: `{:g}`
для 1234.5678 — ветка 1.x печатает `1234.57`, ветки 3.x и 4.x печатают
`1234.5678`. Это и есть содержательная причина верхней границы `<2.0.0`, а
не только floor Dart.

## Проверка

Матрица `flutter pub get` в пробном приложении с path-зависимостью, дважды —
с `flutter_localizations` и без:

| Flutter | без l10n | с l10n |
| --- | --- | --- |
| 3.27.0 | OK | OK |
| 3.29.0 | OK | OK |
| 3.44.4 | OK | OK |
| 3.47.0 | OK | OK |

На 3.27 резолвятся: format 1.5.2, intl 0.19.0, characters 1.3.0, meta
1.15.0, clock 1.1.1, stack_trace 1.12.0, ansi_escape_codes 4.0.1,
logger_builder 0.6.1, archive 4.0.9.

Полный набор (419 тестов) прогнан на обеих допустимых версиях `format` —
зелёный. `dart analyze` и `dart format` чисты в обоих пакетах, пример
работает.

## Что осталось незакрытым

`format` 3.x/4.x, `lints` 6.x (Dart ^3.8.0) и `test` 1.27+ (Dart ^3.7.0)
требуют SDK выше нашего floor'а, поэтому не обновлялись. Все они станут
доступны, если минимальная линия однажды поднимется до Flutter 3.29.2.

## Продолжение в тот же день: format 4.1.0

Пока шла работа, вышла `format` 4.1.0 и обнулила компромисс: она опустила
свой floor с Dart `^3.7.2` обратно до `^3.6.0` (то есть Flutter 3.27
снова годится), а зависимости от `intl` у ветки 4.x нет с 3.0.0. То самое
«заманчиво, но недоступно» из раздела выше стало доступно без цены.

Ограничение теперь `format: ^4.1.0`. Что это даёт:

- `intl` уходит из графа зависимостей всякого приложения, которое берёт
  этот пакет. На Flutter 3.27 с `flutter_localizations` он остаётся в
  lock-файле, но уже как зависимость самого `flutter_localizations`, а не
  наша; в приложении без локализации его нет вовсе.
- одна ветка `format` у всех пользователей вместо двух — предсказуемое
  форматирование чисел.

Цена — ровно одно изменение вывода, которое и нашли тесты: `{:g}` для
1234.5678 печатается как `1234.5678`, где ветка 1.x печатала `1234.57`.
Ожидание в `number_format_test.dart` переставлено на поведение 4.x, а
комментарий рядом хранит прежнее значение — при следующем обновлении
границу будет видно.

Матрица пересобрана на новом ограничении: Flutter 3.27.0, 3.29.0, 3.44.4,
3.47.0, с `flutter_localizations` и без — восемь из восьми. На 3.27
резолвится `format` 4.1.0, `characters` 1.3.0, `meta` 1.15.0, `clock`
1.1.1, `stack_trace` 1.12.0. Из незакрытого остались только dev-зависимости
(`lints` 6.x требует Dart ^3.8.0, `test` 1.27+ — ^3.7.0).
