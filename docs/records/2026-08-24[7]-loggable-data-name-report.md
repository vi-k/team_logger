# Дефект `LoggableData.name`

## Симптом

О дефекте сообщил владелец: в 0.7.0 `LoggableData.name` возвращает строку
`'type'` — всегда, для любого объекта, независимо от имени класса.

Воспроизведение (до правки):

```dart
final data = Loggable.builder(0, name: 'Point')..prop('x', 1);
data.name;              // 'type'      ← ожидалось 'Point'
data.toLogString();     // 'Point(x: 1)'  ← вывод правильный

data.name = 'Renamed';
data.name;              // 'type'      ← сеттер отработал, геттер не видит
data.toLogString();     // 'Renamed(x: 1)'
```

## Причина

`LoggableData` хранит имя класса в `TypeProp _type` — это `Prop<Type>`, у
которого два разных «имени»:

- `Prop.name` — **ключ самого свойства**. Конструктор `TypeProp._` передаёт
  его в `super._('type', type)` литералом, поэтому он равен `'type'` у
  любого `TypeProp`;
- `TypeProp.typeName` — **имя класса** для вывода, `null`, когда имя не
  задано (тогда берётся сам тип).

Сеттер писал в `typeName` (`_type.copyWith(name: value)`), а геттер читал
`_type.name`, то есть ключ свойства:

```dart
String get name => _type.name;      // всегда 'type'
set name(String value) {
  _type = _type.copyWith(name: value);   // пишет в typeName
}
```

Пара геттер/сеттер работала с разными полями. Внутри пакета имя бралось
правильно и мимо геттера — `_type.typeName ?? _type.value.toString()` в
`toJson` и в `toLogString`, — поэтому **вывод всегда был верным**, и наружу
дефект торчал ровно одним местом: чтением `data.name`.

Дублирование этого выражения в двух местах и было условием, при котором
дефект мог жить незамеченным: третий читатель (сам геттер) не был обязан
совпадать с ними и не совпал.

## Правка

`lib/src/loggable/loggable_data.dart`:

```dart
String get name => _type.typeName ?? _type.value.toString();
```

Тип возвращаемого значения остался `String` — это не ломающее изменение.
Вариант «вернуть `_type.typeName`» (то есть `String?`) отвергнут: он ломает
сигнатуру ради того же ответа в другой упаковке, а вопрос «какое имя увидит
читатель лога» имеет ответ всегда.

Заодно оба внутренних вычисления имени (`toJson`, `toLogString`) переведены
на этот же геттер — теперь источник имени один, и разойтись им негде.
Геттер получил dartdoc, который прямо называет ловушку: `TypeProp.name` —
ключ свойства, имя класса — `TypeProp.typeName`.
