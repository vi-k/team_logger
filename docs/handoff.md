## Известные ограничения и техдолг

Найдено ревью, сознательно отложено:

- Ширина wide-символов (CJK, эмодзи) считается в code units — колонки в
  консольном выводе съезжают; нужен учёт восточноазиатской ширины.
- Все свойства builder'а выброшены правилом — блок данных остаётся с
  висящим двоеточием (`login: `). Для multi-data это починено (обход
  секций сообщает о дропе), для `LoggableData` аналога нет: пустой рендер и
  «всё выброшено» неразличимы (находка кросс-ревью 0.7.0).
- Наследование config корневой заменой сделано только для
  `LoggableMultiData` и `LoggableWrapper`; `Loggable.builder(config:)` и
  `mapBuilder(config:)` свой config замене не передают. Не регрессия (так
  было всегда) и все рендереры согласованы между собой, но после введения
  политики «config описывает способ печати и наследуется» выглядит
  непреднамеренным пробелом.
- `FileLogStorage` с упавшей инициализацией (`_disabled`) выбрасывает логи
  молча: в `onDropped` они не идут, туда попадает только отказ по
  `maxQueueSize`. Само состояние сообщается через `onError` один раз.

Ограничение про точечный override уровня («отвязывает подлоггер целиком»)
снято: `logger_builder` 0.7.0 его починил, у нас на это есть регрессионный
тест в `test/logger/logger_test.dart`.
