## Известные ограничения и техдолг

Найдено ревью, сознательно отложено:

- Ширина wide-символов (CJK, эмодзи) считается в code units — колонки в
  консольном выводе съезжают; нужен учёт восточноазиатской ширины.
- Все свойства builder'а выброшены правилом — блок данных остаётся с
  висящим двоеточием (`login: `). Для multi-data это починено (обход
  секций сообщает о дропе), для `LoggableData` аналога нет: пустой рендер
  и «всё выброшено» неразличимы.
- Наследование config корневой заменой сделано только для
  `LoggableMultiData` и `LoggableWrapper`; `Loggable.builder(config:)` и
  `mapBuilder(config:)` свой config замене не передают. Не регрессия, но
  после введения политики «config описывает способ печати и наследуется»
  выглядит непреднамеренным пробелом.
- Локалезависимого форматирования чисел у пакета больше нет вовсе:
  `format` читает `NumberLocale` из инстанса `Format`, а тема зовёт
  топ-уровневый `format()`. Вернуть — это фича, не правка документации.

## Следующий шаг

Следующая открытая Medium-находка — №9: опасные параметры нескольких public
constructor'ов проверяются только через `assert`, а assertions в обычном
production-запуске Dart выключены. Воспроизведение: `LogStorage(maxCount: 0)`
успешно создаётся, но первая публикация падает с `RangeError` уже в точке
логирования; `ConsoleLogPrinter(activeTags: {...})` без `inactiveTheme` также
создаётся, хотя такой фильтр не может выполнить обещанный контракт. Такие же
assert-only границы есть у размеров `FileLogStorage`, темы и collection limits.

Последствия: ошибка конфигурации проявляется далеко от конструктора падением
production logger'а, молча неверным фильтром либо нарушением file-size
инвариантов; обычные тесты с включёнными assertions маскируют проблему.
Следующий шаг — перед кодом согласовать охват: заменить пользовательские
assert-проверки обычными `ArgumentError.value`, сохранив assert только для
внутренних невозможных состояний, и закрепить каждую публичную границу тестом
без зависимости от assertion mode.

До ревью подготовка 0.7.0 (пункты 1–6 чеклиста «Релиз» в
`docs/conventions.md`) была завершена и подтверждена dry-run'ом. Теперь
открыты две Medium/P2 и пять Low/P3; до исправления Medium или их явного
принятия владельцем считать релиз production-ready нельзя. Для самой
релизной связки в любом случае нужен отдельный запрос владельца, состоящий
только из просьбы опубликовать (`AGENTS.md`, раздел «Публикация на pub.dev»).
Разрешения не спрашивать и публикацию не предлагать.

В соседнем репозитории `~/development/my/logger_builder` идёт своя работа.
Это не наше — не трогать; мы его только потребляем с pub.dev.
