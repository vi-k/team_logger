# AGENTS.md

Точка входа для агентов (Claude Code, Codex и любых других). `CLAUDE.md`
ссылается сюда, отдельного набора правил для Claude нет.

## Первое, что нужно сделать в новой сессии

Сессия может оборваться в любой момент. Восстановление начинается отсюда:

1. Прочитать `docs/handoff.md` — текущее состояние проекта: где остановились,
   что не закоммичено, что сломано, каков следующий шаг.
2. Посмотреть `git status` и `git log --oneline -10` — сверить реальность с
   тем, что написано в handoff.
3. Если в handoff указана незавершённая работа, поднять связанную запись из
   `docs/records/` — там спека/план/отчёт по этой работе.
4. Заглянуть в `docs/backlog.md` — записи владельца. Если текущей работы нет,
   предложить владельцу взять оттуда следующий пункт.

Перед тем как трогать код, прочитать `docs/architecture.md` (устройство
пакета) и `docs/conventions.md` (как здесь принято писать код, коммиты и
документы).

В Claude Code шаг 1 выполняется сам: `.claude/settings.json` содержит хук
`SessionStart`, который на старте, резюме и после `/clear` печатает
`docs/handoff.md` в контекст. Codex читает этот файл (`AGENTS.md`)
автоматически и дальше действует по списку выше.

## Карта документов

| Файл | Что внутри | Кто пишет |
| --- | --- | --- |
| `AGENTS.md` | правила работы, точка входа | агент |
| `docs/handoff.md` | **текущее** состояние проекта | агент |
| `docs/backlog.md` | пожелания и задачи владельца | **только владелец** |
| `docs/architecture.md` | устройство пакета, что меняется редко | агент |
| `docs/conventions.md` | соглашения по коду, докам, коммитам | агент |
| `docs/records/` | история: спеки, планы, отчёты, ревью | агент |
| `CHANGELOG.md`, `README.md` | публичные артефакты пакета (по-английски) | агент |

Границы, которые нельзя размывать:

- `docs/handoff.md` — **только текущее состояние**. Не пересказ истории
  коммитов, не разбор законченных эпизодов (это `docs/records/`), не
  пожелания владельца (это `docs/backlog.md`).
- `docs/backlog.md` — агент в него **не пишет**. Только читает, предлагает
  взять пункт в работу и удаляет сделанное после завершения.
- `docs/architecture.md` — только устойчивое устройство. Всё, что меняется
  от недели к неделе, живёт в `docs/handoff.md`.

## Поддержание handoff в актуальном виде

`docs/handoff.md` пишется так, чтобы агент, который откроет его через минуту
после обрыва сессии и ничего не помнит, смог продолжить работу.

Обновлять:

- когда начинается новая работа (что делаем и зачем);
- после каждого коммита или заметного шага;
- когда рабочее дерево осталось грязным (что именно не закоммичено и
  почему);
- когда меняется статус проверок (`dart test`, `dart analyze`);
- перед длинной операцией, результат которой можно не увидеть.

Записи в handoff — короткие и проверяемые: версия, ветка, статус проверок,
следующий шаг. Всё, что стало историей, переезжает в `docs/records/`.

## Рабочий цикл

1. Взять задачу (из `docs/backlog.md` или от владельца), отразить её в
   `docs/handoff.md`.
2. Для нетривиальной работы — спека и/или план в `docs/records/` (имена см.
   в `docs/conventions.md`).
3. Реализация. Тесты обязательны: `dart test`, `dart analyze`,
   `dart format .`.
4. Коммит прямо в `main`, без PR. **Чужие правки не коммитить вместе со
   своими** — если в рабочем дереве есть изменения, которых ты не делал,
   коммить только свои файлы (`git add <файлы>`), а про чужие написать в
   handoff.
5. Обновить `docs/handoff.md`; сделанный пункт удалить из
   `docs/backlog.md`; при завершении работы — отчёт в `docs/records/` и
   шапка «Состояние на …» в связанных записях.
6. После завершения работ в пакете — предложить владельцу
   commit/push/publish (перед публикацией показать дифф).

## Команды

Из корня репозитория:

```bash
dart pub get                              # зависимости
dart test                                 # все тесты
dart test test/team_logger_test.dart      # один файл
dart test -n 'objectToJson'               # тесты по подстроке имени
dart analyze                              # строгий анализ
dart format .                             # форматирование
```

Пример — отдельный пакет, запускать из `example/`:

```bash
cd example && dart pub get
dart run bin/example.dart                 # основной пример
dart run build_runner build               # перегенерировать *.freezed.dart
```

`scripts/ansi_screenshot.sh` рендерит ANSI-вывод в PNG для `screenshots/`
(используются в README).

## Язык

- Документы для владельца и агентов (`AGENTS.md`, `docs/*.md`,
  `docs/records/`) — по-русски. С владельцем общаться по-русски.
- Публичные артефакты — по-английски: `README.md`, `CHANGELOG.md`,
  dartdoc в `lib/`, сообщения коммитов, тексты ошибок.
- Комментарии внутри `lib/src/loggable/` исторически по-русски — держать
  единообразие с окружающим файлом.
